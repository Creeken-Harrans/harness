# 第三章 大语言模型基础

## 原教程讲了什么

hello-agents 第三章覆盖了 LLM 的技术基础：

- **Transformer 架构**：self-attention、multi-head attention、positional encoding
- **Tokenization**：BPE 分词原理，token 与字符的关系
- **Prompt Engineering**：system prompt、few-shot、chain-of-thought 等技巧
- **Chat Completion API**：`/v1/chat/completions` 接口格式，message roles（system/user/assistant）
- **OpenAI Python SDK** 基础用法

**不足**：原教程使用 OpenAI SDK 的同步调用方式（`response = client.chat.completions.create()`），不涉及 streaming 模式。Streaming 在教程中被一笔带过，但工程中 streaming 是必需品而非可选项——用户不想等 10 秒看一个完整回答，他们想看到逐字输出。更重要的是，教程没有涉及 tool calling 在 streaming 模式下的特殊处理：tool call 的 id、function.name、function.arguments 是分多个 SSE chunk 逐字段到达的，需要正确的增量累积逻辑，这是 Agent 框架中最容易出 bug 的地方之一。

**本 harness 的改进**：`DeepSeekClient.chatStream()` 返回 `AsyncGenerator<ModelStreamEvent>`，将 SSE 字节流解析为 5 种类型化事件（content_delta / reasoning_delta / tool_call_delta / choice_done / done）。`runAgentLoop` 中的 `accumulateToolCall()` 正确处理 tool call delta 的逐字段累积。同时，harness 刻意不做通用 ModelProvider 抽象——DeepSeekClient 是唯一的主模型客户端，这避免了为"支持多个 provider"而牺牲 DeepSeek 独有特性（reasoning_content、thinking mode）。

## 本 Harness 如何映射

模型层严格聚焦 DeepSeek API，形成一条完整的 **配置 → 请求 → SSE 解析 → 类型化事件** 流水线：

```
.env (DEEPSEEK_API_KEY / DEEPSEEK_MODEL / DEEPSEEK_THINKING)
  → src/config/config.ts (readConfig: 读取 + 类型化)
    → src/deepseek/client.ts (DeepSeekClient.chatStream: 构造请求 + fetch + SSE 逐块读)
      → src/deepseek/stream.ts (parseDeepSeekSse: buffer → 按 \n\n 分割 → JSON.parse → streamEventsFromChunk)
        → src/deepseek/types.ts (ModelStreamEvent: content_delta | reasoning_delta | tool_call_delta | choice_done | done)
```

核心文件：
- `src/deepseek/client.ts` — `DeepSeekClient`，封装 `/v1/chat/completions` 请求，支持 thinking mode（`reasoning_effort`）、`tool_choice: "auto"`、streaming
- `src/deepseek/stream.ts` — SSE 解析的完整实现：`parseDeepSeekSse()` 返回 `AsyncGenerator<DeepSeekStreamChunk>`，`streamEventsFromChunk()` 将 chunk 展开为 5 种类型化事件
- `src/deepseek/types.ts` — DeepSeek 专有类型：`DeepSeekStreamChunk`（raw chunk）、`ModelStreamEvent`（类型化事件）、`DeepSeekThinking`（thinking mode 配置）
- `src/messages/message.ts` — `ChatMessage` 类型（system/user/assistant/tool roles，支持 `tool_calls` 数组和 `reasoning_content` 字段），DeepSeek/OpenAI 兼容
- `src/messages/serializers.ts` — `toDeepSeekMessages()` 将内部 message 转为 API 格式，`toolResultToMessage()` 将 tool 执行结果序列化为 tool role message
- `src/config/config.ts` — `readConfig()` 从 `.env` 读取所有模型参数，类型化返回 `HarnessConfig`

## 原理解析：为什么不做通用 ModelProvider

hello-agents 教程使用通用 OpenAI 兼容客户端，可以切换不同的 API provider。但本 harness **刻意不做**通用 ModelProvider 抽象。原因：

1. **DeepSeek 有独特的能力**：`reasoning_content`（思考链）、tool-call delta streaming、thinking mode——这些不是所有 provider 都有
2. **避免抽象泄漏**：通用 provider 接口要么太宽（覆盖所有 provider 的交集），要么太窄（只能用最小公分母）
3. **YAGNI**：这个 harness 的目标用户是学习 Agent 工程的人，不是需要切换 5 个 provider 的生产系统

因此，`DeepSeekClient` 是唯一的主模型客户端。它处理：

- DeepSeek-compatible message 格式（system/user/assistant/tool roles，tool_calls 数组，reasoning_content）
- Streaming（SSE 解析，`stream: true`）
- thinking mode（`thinking: { type: "enabled" }` + `reasoning_effort`）
- tool_choice: "auto"

## 操作指南

### 模型配置

```bash
# .env 中的关键配置
DEEPSEEK_API_KEY=sk-your-key    # 必填
DEEPSEEK_MODEL=deepseek-v4-flash # 或 deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_THINKING=disabled       # enabled 开启 reasoning
DEEPSEEK_REASONING_EFFORT=high   # high 或 max
```

### 理解 streaming 流程

在 `src/deepseek/stream.ts` 中，`parseDeepSeekSse` 是一个 `AsyncGenerator`，逐块产出 `ModelStreamEvent`：

```
SSE bytes from network
  → buffer + 按 \n\n 分割
    → 解析 "data:" 行
      → JSON.parse → DeepSeekStreamChunk
        → streamEventsFromChunk() 展开为 ModelStreamEvent:
          - content_delta      (模型输出的文字增量)
          - reasoning_delta    (思考过程增量)
          - tool_call_delta    (工具调用增量: id/name/arguments 逐字段到达)
          - choice_done        (单次 choice 完成，含 finish_reason、usage)
          - done               (stream 结束)
```

**关键设计**：`tool_call_delta` 的处理。

DeepSeek 在 streaming 模式下，tool call 是逐字段增量传输的：

```
chunk 1: tool_calls[0].id = "call_xxx"
chunk 2: tool_calls[0].function.name = "read"
chunk 3: tool_calls[0].function.arguments = '{"path"'
chunk 4: tool_calls[0].function.arguments = ':"package.json"}'
```

`runAgentLoop` 中的 `accumulateToolCall()` 函数负责把这些增量拼接成完整的 `ToolCall` 对象。这是 Agent 框架中最容易出 bug 的地方之一——如果拼接逻辑不对，JSON.parse 会失败。

### 如何验证模型调用

不想启动完整 REPL？可以写一个最小测试脚本：

```typescript
// test-deepseek.ts
import { readConfig } from "./src/config/config.js";
import { DeepSeekClient } from "./src/deepseek/client.js";

const config = readConfig();
const client = new DeepSeekClient(config);

for await (const event of client.chatStream(
  [{ role: "user", content: "用中文说'你好世界'" }],
  [] // 不带工具
)) {
  if (event.type === "content_delta") process.stdout.write(event.delta);
  if (event.type === "reasoning_delta") console.log("[reasoning]", event.delta);
}
console.log();
```

运行：
```bash
npx tsx test-deepseek.ts
```

## 超越原教程

| hello-agents 第三章 | 本 harness |
|---|---|
| 通用 OpenAI client | DeepSeek 专用 client，支持 reasoning_content、thinking mode |
| 同步调用演示 | 全链路 SSE streaming + AsyncGenerator |
| ChatCompletion 单一返回 | 区分 content_delta / reasoning_delta / tool_call_delta / choice_done / done |
| 无 tool call delta 处理 | 完整的增量累积 + JSON 拼接 + parse 错误处理 |
| 无类型安全 | 全量 TypeScript 类型（DeepSeekStreamChunk、ModelStreamEvent 等） |
