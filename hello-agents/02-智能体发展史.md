# 第二章 智能体发展史

## 原教程讲了什么

hello-agents 第二章梳理了智能体范式的演进历史，覆盖了：

- **符号主义 Agent**：基于逻辑规则和知识库的早期 AI（如专家系统）
- **反应式 Agent**：直接映射感知到行动，无内部世界模型
- **BDI Agent**：Belief-Desire-Intention 模型，引入心智状态
- **强化学习 Agent**：通过 reward signal 学习策略
- **LLM Agent**：以语言模型为核心推理引擎的新范式，将 ReAct / Plan-Execute / Reflection 作为 prompt 策略引入

**不足**：原教程以历史叙述为主，各范式之间没有统一的代码框架。读者学完后知道"有这些范式"，但不知道如何在一个项目中同时支持多种范式而不写 6 套 while 循环。ReAct、Plan-Execute、Reflection 被呈现为三种独立的算法流程，而非同一底层能力的三种 prompt 表达。

**本 harness 的改进**：统一 Agent 接口 + prompt-contract 设计。6 种 agent mode 共享同一个 `runAgentLoop`，差异仅在于注入的 system instruction 不同。这体现了 LLM Agent 工程的一个核心洞察：**范式差异的本质是 prompt 合约差异，而非控制流差异**。

## 本 Harness 如何映射

本 harness 不是历史博物馆，但它的 `src/agents/` 目录天然覆盖了 LLM Agent 时代的核心范式。所有 agent mode 实现同一个 `Agent` 接口，通过 `createAgent(name)` 工厂创建，在 REPL 中 `/agent <name>` 切换：

| 历史范式 | Harness Agent Mode | 行为特征 |
|---|---|---|
| 反应式 Agent | `SimpleAgent` | 输入→推理→工具调用→输出，无内部状态机，最简路径 |
| ReAct | `ReactAgent` | Thought → Action → Observation 循环，每次 action 前隐式思考 |
| Plan-Execute | `PlanExecuteAgent` | 先列出步骤（写入 TODO.md），再逐步执行，完成后自动标记 |
| Reflection | `ReflectionAgent` | 完成任务后进行自我检查，发现错误则修正 |

核心机制：
- `src/agents/agent.ts` — `Agent` 接口（`name` / `description` / `run()`），所有 mode 的公共契约
- `src/agents/index.ts` — `createAgent(name)` 工厂，根据名称返回对应 Agent 实例
- `src/agents/simple-agent.ts` — 最简实现（12 行），展示 Agent 接口的最小实现方式
- `src/config/config.ts` — `HarnessAgentName` 类型联合，确保切换 agent 时有编译时检查

## 原理解析：Agent 范式的本质差异

hello-agents 教程中，不同范式通常需要不同的代码框架。但本 harness 使用统一的 **prompt-contract agent mode** 设计：

```typescript
// src/agents/agent.ts
export interface Agent {
  name: string;
  description: string;
  run(input: string, ctx: AgentContext): AsyncGenerator<AgentEvent, AgentResult>;
}
```

所有 agent mode 都实现同一个接口，差异仅在于它们注入给 `runLoop()` 的 system instruction 不同。

以 `ReactAgent` 为例（`src/agents/react-agent.ts`）：

```typescript
run(input: string, ctx: AgentContext): AsyncGenerator<AgentEvent, AgentResult> {
  const instruction = [
    "Use a ReAct-style loop internally: decide the next action, " +
    "call a tool when useful, observe the result, and continue " +
    "until the task is answered.",
    "Do not reveal private chain-of-thought.",
    "Stop after the configured max steps and explain what remains.",
  ].join("\n");
  return ctx.runLoop(agentInput(instruction, input));
}
```

**关键洞察**：ReAct、Plan-Execute、Reflection 的本质区别不在于代码流程不同，而在于 **prompt 合约不同**。ReAct 要求模型在每个 action 前隐式思考，Plan 要求先输出 visible plan，Reflection 要求最后做一次自检。这三种行为都可以通过 system prompt 指令 + 同一个 DeepSeek tool-calling loop 实现。

## 操作指南

### 切换 Agent 范式

```bash
# 方式 1：环境变量
HARNESS_AGENT=react npm run dev

# 方式 2：REPL 内切换
/agent react
/agent plan
/agent reflection
/agent coding
/agent research
/agent simple
```

### 观察不同范式的行为差异

用同一个任务测试不同 agent：

```
you> 帮我检查这个项目有没有 CI 配置文件
```

- `simple`：直接调用 glob/grep 工具查找，报告结果
- `react`：先搜索，分析结果，可能需要额外步骤，但行为类似 core loop
- `plan`：先列出步骤（1.搜索 CI 配置 2.分析内容 3.报告），再逐步执行
- `coding`：先检查 README/package.json，再 glob 搜索，符合 inspect-first 风格

**注意**：当前所有 agent mode 都委托给同一个 `runLoop`，行为差异主要通过 system prompt 实现。这不是简化版——这恰恰是 LLM Agent 的核心设计哲学：**用自然语言指令而非代码分支来控制行为**。

## 超越原教程

| hello-agents 第二章 | 本 harness |
|---|---|
| 历史回顾为主 | 可实际运行、切换不同范式 |
| 范式间代码不统一 | 统一 Agent 接口 + prompt-contract |
| 无工具集成 | 每个 mode 都共享同一套 ToolRegistry |
| 概念性 ReAct | `ReactAgent` 在 tool-calling loop 上运行 |
| 无 Plan-Execute 实现 | `PlanExecuteAgent` 有可见 plan + todo 记录 |
