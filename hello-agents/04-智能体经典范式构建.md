# 第四章 智能体经典范式构建

## 原教程讲了什么

hello-agents 第四章是全书最核心的实践章节之一，系统讲解了三种经典 Agent 范式的原理和 Python 实现：

- **ReAct（Reasoning + Acting）**：Thought → Action → Observation 循环。模型先思考（Thought），再决定行动（Action），执行后观察结果（Observation），然后继续思考。原教程通过手工解析模型输出中的 `Thought:` / `Action:` / `Observation:` 标签来实现这一流程。
- **Plan-and-Solve**：先制定完整计划（Plan），再逐步执行（Execute），执行过程中可以根据结果调整计划。原教程通过两阶段 LLM 调用实现——先让模型生成计划，再让模型按计划逐步执行。
- **Reflection**：完成任务后进行自我检查（Self-Reflection），发现错误则修正。原教程在最终输出后再调用一次 LLM 做 critique。

**不足**：第一，三个范式的代码是独立的——三套 while 循环、三套 tool dispatch 逻辑，公共逻辑（模型调用、工具执行、错误处理）重复出现。第二，原教程依赖手工解析模型输出中的标记（`Thought:` 等），这在支持 native tool calling 的现代模型上不再必要——模型的 tool_call 本身就是 Action，tool result message 本身就是 Observation。第三，原教程的 Plan 是模型自由文本输出，没有与任务追踪系统（如 todo list）集成，计划执行完就丢了。

**本 harness 的改进**：用 **prompt-contract agent mode** 替代三套独立循环。三个 Agent 共享同一个 `runAgentLoop`，仅注入不同的 system instruction。利用 DeepSeek 的 native tool calling——tool-call delta 就是 Action，tool result message 就是 Observation——不再需要解析文本标记。PlanExecuteAgent 额外集成了 `TodoStore`，将计划条目写入 `data/notes/TODO.md`，事后可追溯。

## 本 Harness 如何映射

`src/agents/` 下 6 种 agent mode，全部共享同一个 `runAgentLoop`，差异仅在于注入的 system instruction：

| Agent Mode | 对应范式 | 核心 Instruction |
|---|---|---|
| `ReactAgent` | ReAct | "Use a ReAct-style loop internally: decide → call tool → observe → continue" |
| `PlanExecuteAgent` | Plan-and-Solve | "First list steps as a numbered plan, then execute one by one. Update TODO.md as you progress." |
| `ReflectionAgent` | Reflection | "After completing the task, self-check your answer. If errors found, correct them." |
| `SimpleAgent` | 基准（无特定范式） | 无额外 instruction，直接 tool-calling 循环 |
| `CodingAgent` | 编程工作流 | "Inspect before edit, read before write, verify after change." |
| `ResearchAgent` | 本地研究 | "Plan → gather evidence → record notes → synthesize → report." |

关键设计：`PlanExecuteAgent` 不同于其他 mode——它在 instruction 中要求模型先输出 visible plan，然后用 `todo_add` 工具将计划写入 `data/notes/TODO.md`。这利用了 `TodoStore`（`src/notes/todo.ts`）的任务追踪能力——计划不再是一次性的文本输出，而是可查询、可追溯的持久化任务状态。其他 agent 文件（如 `ReactAgent`、`ReflectionAgent`）的实现结构完全一致——每个文件约 15-25 行，仅包含 `name`、`description`、`run()` 方法（调用 `ctx.runLoop(agentInput(instruction, input))`）。

## 原理解析：范式实现的两种路径

hello-agents 教程中，每种范式需要独立的 Python 类，内含独立的 while 循环。例如：

```python
# hello-agents 风格的 ReAct
class ReactAgent:
    def run(self, task):
        while steps < max_steps:
            thought = llm.think(...)
            action = llm.act(...)
            observation = execute(action)
            # 自己管理循环...
```

本 harness 采用不同的策略：**共享同一个 runLoop，通过 prompt 合约区分行为**。

### 方式一：hello-agents（代码分支控制）

```
SimpleAgent.run()  → while loop A
ReactAgent.run()   → while loop B (含 Thought/Action/Observation 标签)
PlanAgent.run()    → while loop C (含 plan 状态机)
```

问题：
- 三个 loop 的 bug 需要修三次
- tool calling、error handling、streaming、trace 需要在三个地方实现
- 无法共享 ToolRegistry、approval policy、context budget

### 方式二：本 harness（prompt 合约 + 共享 loop）

```
SimpleAgent.run()        → runLoop("", input)
ReactAgent.run()         → runLoop("Use ReAct-style loop...", input)
PlanExecuteAgent.run()   → runLoop("Use Plan-Execute mode...", input)
ReflectionAgent.run()    → runLoop("Use Reflection mode...", input)
```

所有 agent 共享同一个 `runAgentLoop`，享受同等的：
- DeepSeek streaming
- ToolRegistry 调度
- Permission/approval 门控
- Trace/Trajectory 记录
- Context budget 管理
- Error handling

### ReAct 的工程化实现

传统 ReAct 需要显式的 Thought/Action/Observation 标签。但在支持 native tool calling 的模型（如 DeepSeek v4）上，这一步不再需要手工解析——**tool-call delta 本身就是 Action，tool result message 本身就是 Observation，content delta 本身就是 Thought**。

因此，`ReactAgent` 的 prompt 指令是：

```
Use a ReAct-style loop internally:
  decide the next action,
  call a tool when useful,
  observe the result,
  continue until the task is answered.
Do not reveal private chain-of-thought.
```

模型会在内部做 Thought（可能表现为 reasoning_content），输出 tool_call（Action），然后 loop 把 tool result 作为 Observation 传回。

## 操作指南

### 用不同范式解决同一个问题

```bash
npm run dev
```

```
/agent simple
you> 写一个函数判断一个数是不是质数，保存到 is_prime.ts

/agent plan
you> 写一个函数判断一个数是不是质数，保存到 is_prime.ts

/agent react
you> 写一个函数判断一个数是不是质数，保存到 is_prime.ts
```

观察差异：
- `simple`：直接写文件
- `plan`：先列出步骤（1.创建文件 2.实现函数 3.验证），再逐步执行，完成后标记 todo
- `react`：类似 simple，但推理风格略有不同

### 对比 trace 差异

```bash
# 对比不同 agent 模式下同一任务的 trace
diff <(cat data/traces/<simple-runId>.jsonl | python3 -c "import sys,json;[print(json.loads(l)['type']) for l in sys.stdin]") \
     <(cat data/traces/<plan-runId>.jsonl | python3 -c "import sys,json;[print(json.loads(l)['type']) for l in sys.stdin]")
```

你会看到 plan mode 多了 `todo_add`、`note_append` 等工具调用。

## 超越原教程

| hello-agents 第四章 | 本 harness |
|---|---|
| 三个独立的 while 循环 | 一个共享 runLoop + prompt 合约 |
| 手工解析 Thought/Action/Observation | 利用 native tool calling（tool-call delta = Action, tool result = Observation） |
| 无安全控制 | 所有 tool call 经过 approval/permission 门控 |
| 无可观测性 | trace + trajectory 自动记录每次 run |
| 仅 Python 示例 | TypeScript 实现 + eval 回归测试 |
