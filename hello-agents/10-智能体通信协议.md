# 第十章 智能体通信协议

## 原教程讲了什么

hello-agents 第十章介绍了智能体生态中的通信协议标准，系统讲解了：

- **MCP（Model Context Protocol）**：由 Anthropic 提出的标准化协议，让 Agent 通过统一的 client-server 模式发现和调用外部工具、访问外部资源。教程展示了如何用现成的 MCP client 连接 MCP server，将 server 提供的 tools 接入 Agent
- **A2A（Agent-to-Agent）**：Google 提出的 Agent 间通信协议，定义了 Agent 如何互相发现能力、发送任务请求、返回结果
- **ANP（Agent Network Protocol）**：去中心化的 Agent 网络协议概念

**不足**：第一，原教程侧重"使用现成 MCP client"——连接即用，但对 MCP 协议内部的 JSON-RPC 消息格式、session 初始化握手、tool 描述到本地 tool 的适配过程没有深入。读者学完后会用，但不知道如何将 MCP tools 集成到自有框架的 ToolRegistry 中。第二，安全性被忽略——外部 MCP tools 直接可用，没有风险分级和审批门控。如果一个 MCP server 提供了 `execute_shell_command` 工具，Agent 可能在没有用户确认的情况下执行危险命令。第三，协议实现状态不透明——教程展示的是"完整可用"的 MCP 使用，但真实项目中协议集成往往是逐步的，读者需要知道哪些部分已实现、哪些还在规划中。

**本 harness 的改进**：为 MCP 和 A2A 提供了**接口先行 + skeleton 实现 + 诚实标注**的设计。`McpClient` 接口（`listTools()` / `callTool()` / `close()`）清晰定义了 MCP client 的契约，`mcpToolToHarnessTool()` 展示了如何将外部 MCP tool 描述适配为 harness 的 `Tool` 接口——关键设计是所有 MCP 引入的工具默认 risk 级别为 `"network"`，**默认需要审批**，这在安全上比"连接即用"更严格。`McpStdioTransport` 实现了基于子进程 stdio 的传输层骨架。`LocalAgentBus` 提供了进程内 Agent 间通信的基础设施。所有协议模块明确标注实现状态（skeleton/TODO），没有任何一行被主路径偷偷 import——它们是明确的 extension point，而非藏在后台的半成品。

## 本 Harness 如何映射

MCP 和 A2A 模块采用**接口先行 + skeleton 实现 + 诚实标注**策略——接口已定义，最小可用代码已写，但完整协议实现是有意保留的 TODO（协议是庞大的工程，不适合在 4400 行的 harness 中完整实现）：

**MCP 模块** (`src/mcp/`)：
- `client.ts` — `McpClient` 接口（`listTools()` / `callTool()` / `close()`）+ `NotConnectedMcpClient` 占位实现，当没有 MCP server 连接时返回空列表
- `stdio.ts` — `McpStdioTransport`：基于 `child_process.spawn` 的 stdio 传输层，`writeJson()` 发送 JSON-RPC 消息。当前缺失：完整的 JSON-RPC 请求/响应/错误格式、session 初始化握手
- `adapter.ts` — `mcpToolToHarnessTool()`：将外部 MCP tool 描述转为 harness `Tool` 接口，关键设计——所有 MCP 工具默认 `risk: "network"`，需审批

**A2A 模块** (`src/a2a/`)：
- `agent-card.ts` — `AgentCard` 类型：`name` / `description` / `capabilities` / `url`，描述一个 Agent 的对外能力
- `local-bus.ts` — `LocalAgentBus`：进程内 Agent 通信——`registerAgent(card, handler)` 注册 + `listAgents()` 发现 + `requestTask(name, input)` 调用
- `protocol-notes.ts` — 诚实标注：明确说明 "Current support is local in-process bus, not remote protocol"

扩展路径清晰：实现 `StdioMcpClient implements McpClient`（补充 JSON-RPC）→ 在 REPL 启动时连接 MCP server → 通过 `mcpToolToHarnessTool()` 注册到 ToolRegistry → Agent 即可使用外部工具。每一步的接口已经就位。

## 原理解析：MCP 在 Harness 中的位置

MCP 的核心思想是：让 Agent 通过标准化协议发现和调用外部工具，而不是在本地硬编码工具。在 harneess 架构中，MCP 应当作为 `ToolRegistry` 的**外部数据源**：

```
                    ┌─────────────────┐
                    │  ToolRegistry    │
                    │                  │
                    │ ┌─────────────┐  │
                    │ │ Core Tools   │  │  ← 本地注册 (shell, file, git, memory...)
                    │ │ (18 tools)   │  │
                    │ └─────────────┘  │
                    │ ┌─────────────┐  │
                    │ │ MCP Tools    │  │  ← 通过 McpClient 发现的外部工具
                    │ │ (future)     │  │
                    │ └─────────────┘  │
                    └─────────────────┘
```

当前骨架已实现的内容：

### McpClient 接口 (`src/mcp/client.ts`)

```typescript
export interface McpClient {
  listTools(): Promise<McpToolDescriptor[]>;
  callTool(name: string, input: Record<string, unknown>): Promise<unknown>;
  close(): Promise<void>;
}
```

### MCP Tool → Harness Tool 适配 (`src/mcp/adapter.ts`)

```typescript
export function mcpToolToHarnessTool(client: McpClient, descriptor: McpToolDescriptor): Tool {
  return {
    name: "mcp_" + descriptor.name,
    description: descriptor.description ?? "MCP tool adapter",
    inputSchema: descriptor.inputSchema ?? { type: "object", properties: {}, additionalProperties: true },
    risk: "network",  // 所有 MCP 工具都标为 network risk（需审批）
    async run(input) {
      const data = await client.callTool(descriptor.name, input);
      return { ok: true, content: JSON.stringify(data, null, 2), data };
    },
  };
}
```

关键设计决策：所有通过 MCP 引入的工具默认 risk 级别为 `"network"`——这意味着**默认需要审批**。这比 hello-agents 教程中"直接连接即用"的方式更安全。

### Stdio Transport (`src/mcp/stdio.ts`)

实现了通过子进程 stdio 与 MCP server 通信的基础传输层：

```typescript
export class McpStdioTransport {
  start(options: McpStdioTransportOptions): void {
    this.child = spawn(options.command, options.args ?? [], { stdio: "pipe" });
  }
  writeJson(message: unknown): void {
    this.child.stdin.write(JSON.stringify(message) + "\n");
  }
}
```

当前缺失：JSON-RPC 消息格式定义、response/error 解析、session 初始化握手。

### A2A Local Bus (`src/a2a/local-bus.ts`)

A2A 是 Agent-to-Agent 通信协议。本 harness 提供了一个进程内的 `LocalAgentBus`：

```typescript
export class LocalAgentBus {
  registerAgent(card: AgentCard, handler: LocalAgentHandler): void;
  listAgents(): AgentCard[];
  async requestTask(name: string, input: unknown): Promise<unknown>;
}
```

这允许在同一个进程中注册多个 Agent（通过 AgentCard 描述能力），然后互相调用。当前是 local in-process，不是远程协议。

### 诚实标注

当前 MCP/A2A 模块没有任何一行被主路径 import。它们是明确的 **extension points**，不是藏在后台运行的半成品。这在 `docs/ROADMAP.md` 和 `README.md` 中有明确标注。

### 未来集成路径（不现在做）

当你准备扩展 MCP 时，集成步骤是清晰的：

1. 实现一个 `StdioMcpClient implements McpClient`（在 `src/mcp/client.ts` 中）
2. 在 `src/cli/repl.ts` 中启动 MCP client，通过 `mcpToolToHarnessTool()` 将 remote tools 注册到 `ToolRegistry`
3. 之后模型就可以通过正常的 tool calling 使用外部 MCP 工具

每一层的接口都已经定义好，只是实现是 stub。
