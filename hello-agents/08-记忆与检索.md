# 第八章 记忆与检索

## 原教程讲了什么

hello-agents 第八章系统讲解了 Agent 记忆系统的概念与实现，覆盖：

- **记忆分类**：短期记忆（对话上下文，在 context window 内）vs 长期记忆（持久化存储，跨会话保留）vs 工作记忆（当前任务状态）
- **RAG 检索增强生成**：将外部文档向量化存入向量数据库，用户提问时检索相关片段注入 context，解决 LLM 知识截止和幻觉问题
- **记忆更新策略**：何时写入新记忆、如何合并重复记忆、记忆衰减/遗忘机制的概念

**不足**：第一，原教程的记忆实现是**单一层次**的——所有持久信息混在一个存储中，没有区分"每次推理都需要的上下文信息"和"按需查阅的任务状态"。如果每次 LLM 调用都注入全部记忆，会大量消耗 context budget。第二，记忆搜索依赖英文关键词匹配或 embedding，对中文不友好——中文分词需要专门的分词器（如 jieba），否则"用户偏好"无法匹配到"用户"和"偏好"。第三，记忆没有区分来源——模型自动保存的、用户手动保存的、工具执行产生的记忆混在一起，无法追溯信息源头。

**本 harness 的改进**：实现了**三层记忆架构**——Context 注入层（`MemoryStore.search()` 检索相关记忆自动注入每次 LLM 调用）、Notes 工具访问层（NOTES.md / TODO.md / DECISIONS.md 等通过 `note_read` / `todo_list` 工具按需访问，不自动注入以节省 context budget）、Session 层（`SessionStore` 管理对话历史）。记忆搜索在英文关键词基础上额外实现了**中文 bigram 匹配**——将中文文本拆为单字和相邻二字词，不依赖分词器也能做基本的语义对齐。每条记忆标记 `source` 字段（`user` / `assistant` / `tool` / `manual`），可追溯信息来源。MemoryStoreInterface 定义了 working/episodic/semantic/procedural 四种记忆类型，SQLite/vector 为明确的 TODO skeleton 而非伪装已有。

## 本 Harness 如何映射

本 harness 实现了**三层记忆架构**，每一层有不同的访问方式和使用场景：

| 层次 | 存储 | 访问方式 | 生命周期 |
|---|---|---|---|
| **Context 注入层** | `MemoryStore` (`data/memory.json`) | `ContextBuilder` 每次 LLM 调用前通过 `memory.search()` 检索 8 条相关记忆，自动注入 system message | 跨会话持久 |
| **工具访问层** | `NotesStore` (`data/notes/*.md`) | Agent 通过 `note_read` / `todo_list` / `decision_list` 等工具按需查阅，**不自动注入**以节省 context budget | 跨会话持久 |
| **会话层** | `SessionStore` (`data/sessions/*.json`) | 完整对话历史，直接追加到 messages 数组 | 单次会话 |

核心模块：
- `src/memory.ts` — `MemoryStore` 兼容层：`add()` / `search()` / `list()` / `remove()`，JSON 文件持久化，中文 bigram 搜索
- `src/memory/memory.ts` — `MemoryStoreInterface`：定义了 working / episodic / semantic / procedural 四种记忆类型，为未来 SQLite+vector 实现预留接口
- `src/memory/search.ts` — 搜索工具函数：英文 `\p{L}\p{N}` token 匹配 + 中文单字 + 相邻二字词（bigram），不依赖分词器
- `src/memory/sqlite-store.ts` — `SqliteMemoryStore` skeleton（TODO），接口已定义，实现待完成
- `src/session.ts` — `SessionStore`：管理对话历史，支持多 session（`default` / 自定义名称），JSON 文件持久化
- `src/notes/notes.ts` + `src/notes/todo.ts` — Notes/Todo 管理：`NOTES.md` / `TODO.md` / `DECISIONS.md` / `ERRORS.md` / `PROGRESS.md`
- `src/tools/core/memory.ts` — `memory_add` / `memory_search` / `memory_list` 工具，Agent 可主动管理记忆
- `src/tools/core/notes.ts` — `note_read` / `note_append` / `todo_add` / `todo_list` 等工具，Agent 可读写任务笔记

## 原理解析：记忆层次架构

hello-agents 教程将记忆分为短期（对话上下文）和长期（持久存储+RAG）。本 harness 进行了更细致的分层：

```
┌──────────────────────────────────────────────────┐
│ Context Builder (每次 LLM 调用前构建)              │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ Session   │ │ Memory   │ │ SOUL + AGENTS.md │  │
│  │ History   │ │ Search   │ │ (static rules)   │  │
│  │ (短期)    │ │ (长期)    │ │                  │  │
│  └──────────┘ └──────────┘ └──────────────────┘  │
├──────────────────────────────────────────────────┤
│ Notes/Todo (任务状态)                              │
│  NOTES.md / TODO.md / DECISIONS.md / ERRORS.md    │
│  (通过工具访问，不自动注入 context)                  │
├──────────────────────────────────────────────────┤
│ Memory Store (持久层)                              │
│  data/memory.json  ←── 当前实现                    │
│  [future] SQLite + vector ←── TODO                 │
└──────────────────────────────────────────────────┘
```

### 为什么 Notes 不自动注入 Context？

这是一个有意识的设计决策。Notes（NOTES.md, TODO.md, DECISIONS.md, ERRORS.md, PROGRESS.md）是**长程任务状态**，而非每次推理都需要的信息。如果每次 LLM 调用都注入全部 notes，会大量消耗 context budget。

替代方案：Agent 通过 `note_read`、`todo_list` 等工具**按需访问** notes。这更接近人类的工作方式——你不会每 5 分钟重读一遍所有笔记，而是需要时才查阅。

### 记忆搜索：中文友好设计

`src/memory.ts` 的 `search()` 方法同时处理英文关键词和中文二字词（bigram）：

```typescript
function terms(input: string): Set<string> {
  // 英文/数字 token: 匹配 \p{L}\p{N}_- 连续字符 (>=2)
  for (const m of s.matchAll(/[\p{L}\p{N}_-]+/gu)) {
    if (token.length >= 2) out.add(token);
  }
  // 中文: 单字 + 相邻二字词 (bigram)
  const han = [...s.matchAll(/[\p{Script=Han}]/gu)].map(m => m[0]);
  for (let i = 0; i < han.length; i++) {
    out.add(han[i]);
    if (i + 1 < han.length) out.add(han[i] + han[i + 1]);
  }
}
```

这使得"用户偏好"可以匹配到"用户"和"偏好"的二字组合，不需要 embedding 也能做基本的语义对齐。

### memory_add 工具的行为

当模型调用 `memory_add` 工具时（`src/tools/core/memory.ts`）：

```typescript
run(input, ctx) {
  const entry = ctx.memory.add(text, tags, "assistant");
  return { ok: true, content: `Saved memory ${entry.id}`, data: { saved: entry } };
}
```

注意 `source: "assistant"` — 这标记了这条记忆是由 Agent 主动保存的，与用户通过 `/remember` 命令手动保存的记忆（`source: "manual"`）区分开。

## 操作指南

### 手动管理记忆

```bash
npm run dev

# 手动保存记忆
/remember DeepSeek API 默认 base URL 是 https://api.deepseek.com

# 搜索记忆
/mem DeepSeek URL

# 列出所有记忆
/mem

# 查看记忆文件
cat data/memory.json | python3 -m json.tool
```

### 让 Agent 自动使用记忆

```
you> 记住：这个项目的代码风格是 2 空格缩进，不用 tab
```

模型收到这个指令后，应该调用 `memory_add` 工具保存这条偏好。下次对话时，`ContextBuilder` 会通过 `memory.search(latestUserInput, 8)` 检索相关记忆并注入 context。

验证：
```bash
# 查看本次 context build 中是否注入了记忆
/context
# 输出中的 "memoryHits" 字段表示本次命中的记忆数
```

### 查看 notes 系统

```bash
# 查看所有 notes 文件
ls data/notes/

# Plan agent 会自动写 todo
/agent plan
you> 帮我重构 src/runtime/loop.ts，拆成更小的函数

# 查看自动记录的 todo
/todo
```
