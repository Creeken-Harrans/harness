# 第十四章 自动化深度研究智能体

## 原教程讲了什么

hello-agents 第十四章介绍了 DeepResearch（深度研究）Agent 这一高级 Agent 范式，系统讲解了：

- **DeepResearch 的概念**：与简单问答 Agent 不同，DeepResearch 需要自动进行多步信息收集、交叉验证来源、分析矛盾信息、综合多源线索、生成结构化研究报告——这是一个可能需要数十步工具调用的长程任务
- **核心流程**：Planner（分解研究问题为子问题）→ Gatherer（web search、文档检索收集信息）→ Analyzer（分析收集到的信息，提取关键事实）→ Synthesizer（综合多源信息，形成结论）→ Reporter（生成带引用的结构化研究报告）
- **工具需求**：web search API、网页抓取、文档解析、引用管理
- **实现示例**：用 Python 实现一个能搜索网页、抓取内容、生成研究报告的 Agent

**不足**：第一，搜索 API 调用混合在 Agent 代码中——如果搜索 API 换厂商（如 Google → Brave），需要修改 Agent 核心逻辑。正确的做法是将搜索抽象为 Tool 接口，让搜索能力的变更不影响 Agent 行为。第二，没有诚实标注能力边界——教程的 DeepResearch 示例依赖特定的搜索 API，但没有明确告诉读者"如果没有这个 API，Agent 能做什么、不能做什么"。第三，研究过程不可追溯——Agent 做了多步搜索和分析，但没有自动记录每一步的发现和决策，事后无法审查信息来源。第四，联网搜索没有安全门控——Agent 直接调用搜索 API，没有审批机制。

**本 harness 的改进**：提供了 `ResearchAgent` 作为本地文档研究 agent，关键设计是**诚实标注**——当前只有本地文件搜索能力（`grep` / `glob` / `read_file`），prompt 中明确告诉模型 "No web/search tool is currently registered, so do not claim live web research"。这避免了常见的"Demo 中假装有 DeepResearch"问题。搜索能力通过 Tool 接口解耦——当你准备好接入 Brave Search API 时，只需实现一个新的 `web_search` Tool（实现 `Tool` 接口，标记 `risk: "network"`），注册到 ToolRegistry，ResearchAgent 就能自动使用。研究过程通过 `note_append` / `decision_record` 自动记录，notes 文件事后可审查。网络工具默认 `risk: "network"` 需要审批——即使将来接入搜索 API，安全门控也已经在位。

## 本 Harness 如何映射

`ResearchAgent` (`src/agents/research-agent.ts`) 是本章的对应实现。**诚实标注**：当前是本地文档研究 agent，不是联网 DeepResearch。

DeepResearch 的五阶段流程在 harness 中的映射：

| 阶段 | Harness 实现 | 说明 |
|---|---|---|
| 1. Planner | `ResearchAgent` 的 system instruction | "Plan the research question, decompose into sub-questions" |
| 2. Gatherer | `grep` / `glob` / `read_file` + `memory_search` | 从 workspace 文件和持久记忆中收集证据，当前无 web search |
| 3. Analyzer | LLM 推理（content delta） | 模型分析收集到的信息，提取关键事实 |
| 4. Synthesizer | LLM 推理 + `note_append` / `decision_record` | 综合多源信息形成结论，记录到 NOTES.md / DECISIONS.md |
| 5. Reporter | `write_file` | 生成结构化研究报告（Markdown），保存到 workspace |

核心文件：
- `src/agents/research-agent.ts` — `ResearchAgent`（~25 行）：注入研究流程 instruction + 诚实声明 "No web/search tool is currently registered"
- `src/tools/core/file.ts` — `grep` / `glob` / `read_file` / `write_file`：本地文档搜索与报告输出
- `src/tools/core/notes.ts` — `note_append` / `decision_record`：记录研究发现和决策过程
- `src/tools/core/memory.ts` — `memory_search`：从持久记忆中检索相关信息

扩展路径：接入 web search 只需实现一个 `Tool` 接口（`name: "web_search"`, `risk: "network"`），注册到 ToolRegistry，更新 ResearchAgent 的 instruction 去掉 "No web/search tool" 限制。不改任何框架代码。

## 原理解析：DeepResearch 的本质

无论是 OpenAI 的 DeepResearch 还是 hello-agents 的实现，深度研究 Agent 的核心流程是：

```
1. Planner:   理解研究问题，分解为子问题
2. Gatherer:  搜索/收集信息（web search, document retrieval）
3. Analyzer:  分析收集到的信息
4. Synthesizer: 综合多源信息
5. Reporter:  生成结构化研究报告
```

本 harness 的 `ResearchAgent` 实现了这个流程的**本地文档版本**：

```typescript
export class ResearchAgent implements Agent {
  name = "research";
  description = "Local-document research agent with planner, gather, notes, synthesize, report phases.";

  run(input, ctx) {
    const instruction = [
      "Use Research Agent mode for local materials.",
      "Plan the research question, gather evidence from workspace files and memory, " +
      "record useful notes, then synthesize a grounded report.",
      "No web/search tool is currently registered, so do not claim live web research.",
    ].join("\n");
    return ctx.runLoop(agentInput(instruction, input));
  }
}
```

**为什么诚实标注"无联网搜索"很重要？**

很多 Agent 框架在 Demo 中假装有 DeepResearch，实际上只是在 system prompt 中说"你是研究助手"。真正的 DeepResearch 需要：
- Web search tool（如 Brave Search API、SerpAPI）
- 大规模文档检索（如向量数据库）
- 长上下文管理（研究报告可能很长）
- 引用追踪

本 harness 选择诚实：**当前只有本地文件搜索能力，明确告诉模型不要假装有联网搜索**。

### 如何"超越"原教程

hello-agents 给你一个 DeepResearch Agent 的 Python 实现。本 harness 给你的价值是：

1. **理解 DeepResearch 的工程结构**：planner → gather → notes → synthesize → report 这个流程是通用的，不限于研究任务
2. **看到限制并理解为什么**：没有 web search tool 时 Agent 能做什么、不能做什么
3. **知道如何扩展**：当你准备好接入 Brave Search API 时，只需要写一个新的 Tool（实现 `Tool` 接口），注册到 ToolRegistry，ResearchAgent 就能自动使用

## 操作指南

### 本地文档研究

```bash
npm run dev

# 切换到 research mode
/agent research

# 提出研究任务（以 harness 项目自身为例）
you> 研究这个项目的安全机制：
     1. 有哪些安全层次？
     2. 审批策略是什么？
     3. 路径策略如何工作？
     4. 脱敏覆盖哪些信息？
     生成一份安全分析报告，保存为 security_report.md。
```

Agent 会：
1. 使用 `grep` 搜索代码中的安全相关关键词
2. 使用 `read_file` 读取 `src/security/*.ts`
3. 调用 `note_append` 记录发现
4. 综合信息生成报告
5. 调用 `write_file` 保存报告

### 观察研究过程

```bash
# 查看自动记录的笔记
/notes NOTES.md

# 查看自动记录的决策
/notes DECISIONS.md
```

### 对比：联网 vs 本地

```
联网 DeepResearch:
  Input: "2024年 AI Agent 领域的顶级论文有哪些"
  → web search → 收集论文列表 → 阅读摘要 → 分类 → 生成报告

本地 ResearchAgent:
  Input: "2024年 AI Agent 领域的顶级论文有哪些"
  → grep "Agent" papers/*.md → 找到本地已有的论文
  → 如果 workspace 中没有论文，诚实报告"我只能在本地文件中搜索"
```

### 扩展：添加 Web Search Tool（骨架）

将来如果你想添加联网搜索，只需要实现一个 Tool：

```typescript
const webSearchTool: Tool = {
  name: "web_search",
  risk: "network",          // 联网 = network risk → 需要审批
  description: "Search the web using Brave Search API.",
  inputSchema: {
    type: "object",
    properties: {
      query: { type: "string" },
      limit: { type: "number" },
    },
    required: ["query"],
  },
  async run(input) {
    const query = String(input.query);
    const response = await fetch(`https://api.search.brave.com/...?q=${query}`);
    const results = await response.json();
    return { ok: true, content: JSON.stringify(results), data: results };
  },
};
```

然后在 `src/tools/core/index.ts` 中注册。`ResearchAgent` 的 prompt 需要更新，去掉 "No web/search tool" 的限制，改为 "Use web_search for external information"。

**这就是 harness 的扩展方式：不改任何框架代码，只加一个 Tool + 调 prompt。**
