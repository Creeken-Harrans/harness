# 第十六章 毕业设计

## 原教程讲了什么

hello-agents 第十六章是全书的收官——毕业设计，指导学生综合运用全书知识完成一个完整的 Agent 项目，覆盖：

- **选题方向**：给出多个选题建议——从简单的工具封装到复杂的多 Agent 系统，按难度分级
- **项目结构**：一个标准 Agent 项目的目录布局、模块划分、代码组织方式
- **答辩要点**：如何展示项目——问题定义、技术选型、系统架构、核心创新、Demo 演示
- **项目评估标准**：从代码质量、功能完整度、创新性、文档质量等维度评价

**不足**：第一，原教程给学生的是**选题建议 + 方向指导**，但没有一个可直接在其上做毕业设计的工程基础。学生需要从零搭建 Agent 框架（约 2 周工作量），然后才能开始做选题本身——这导致大量时间花在基础设施而非业务逻辑上。第二，没有可验证的质量标准——`npm run build`、`npm run typecheck`、`npm run eval` 全部通过是一个具体的、可执行的基线，但原教程没有提供这样的自动化验证手段。第三，选题之间没有共享的基础设施——每个学生的项目从零开始，无法站在前人的肩膀上。

**本 harness 的改进**：本 harness 的 `hello-agents/` 目录（你正在读的）就是第十六章的**"参考答案"和工程基础**。它证明了你可以在一个约 4400 行的 TypeScript 项目中实现 hello-agents 全书的核心概念，且 `npm run build && npm run typecheck && npm run eval` 全部通过。更重要的是，它给出了 5 个**可直接开始的选题**（按从浅到深排列）：添加一个新 Tool（约 2 小时）、实现一个新的 Agent Mode（约 4 小时）、重构 ContextBuilder 使用真实 tokenizer（约 8 小时）、接入 MCP Server（约 12 小时）、实现 Agentic RL 训练数据导出管道（约 16 小时）。每个选题都指明了涉及模块、具体步骤、学习要点。学生不需要花 2 周搭框架——**从 `npm run eval` 全部通过的基线出发，用 2-16 小时即可完成选题，因为工具系统、Agent loop、安全边界、trace/eval 基础设施都已经就位**。同时提供了明确的毕业设计质量标准：build 通过、typecheck 通过、eval 通过（现有 case 不被破坏）、新增至少 1 个 case、文档更新、诚实标注。

## 本 Harness 如何映射

本 harness 本身就是第十六章的**"参考答案"和工程基础**——一个通过 `npm run build && npm run typecheck && npm run eval` 的 4400 行 TypeScript 项目，覆盖了 hello-agents 全书的核心概念。

从它出发，以下是 5 个可直接开始的毕业设计选题：

| 选题 | 难度 | 预计时间 | 涉及模块 | 核心学习点 |

| 添加一个新 Tool（如 `weather`） | 新手 | ~2h | `src/tools/tool.ts` → `core/index.ts` → `evals/cases/` | Tool 接口、inputSchema、risk 分级、eval case 编写 |

## 原理解析：毕业设计的选题思路

hello-agents 第十六章给出了几个选题方向。以下是针对本 harness 的选题建议，按从浅到深排列：

### 选题 1: 添加一个新 Tool（新手，约 2 小时）

**目标**: 为 harness 添加一个 `weather` 工具

**涉及模块**: `src/tools/tool.ts` `src/tools/core/index.ts`

**步骤**:
1. 在 `src/tools/core/` 下新建 `weather.ts`
2. 实现 `Tool` 接口（name, description, inputSchema, risk, run）
3. 在 `src/tools/core/index.ts` 的 `createPhase2CoreTools()` 中注册
4. 写一个 eval case 测试它
5. 运行 `npm run eval` 验证

**学习要点**: Tool 接口、inputSchema 定义、risk 选择、eval case 编写

### 选题 2: 实现一个新的 Agent Mode（中级，约 4 小时）

**目标**: 实现一个 `TeacherAgent`，用苏格拉底式提问引导用户学习

**涉及模块**: `src/agents/` `src/config/config.ts`

**步骤**:
1. 新建 `src/agents/teacher-agent.ts`，实现 `Agent` 接口
2. 写 prompt 指令：用提问而非直接给答案，引导用户自己发现
3. 在 `src/agents/index.ts` 中注册
4. 在 `src/config/config.ts` 的 `HarnessAgentName` 类型中添加 `"teacher"`
5. 测试：`/agent teacher` + 提问

**学习要点**: Agent 接口、prompt engineering、agent mode 注册机制

### 选题 3: 重构 ContextBuilder 使用真实 tokenizer（中高级，约 8 小时）

**目标**: 用 `tiktoken` 或 DeepSeek tokenizer 替代 `char/4` 估算

**涉及模块**: `src/context/`

**步骤**:
1. 安装 tokenizer 依赖（如 `js-tiktoken` 或 DeepSeek 兼容的 tokenizer）
2. 修改 `src/context/budget.ts` 的 `approximateTokens()`
3. 确保 `/context` 命令展示真实 token 数
4. 对比 char/4 估算和真实 token 数的差异

**学习要点**: tokenization 原理、context budget 精确控制

### 选题 4: 接入 MCP Server（中高级，约 12 小时）

**目标**: 让 harness 通过 MCP 协议连接外部 tool server

**涉及模块**: `src/mcp/` `src/tools/registry.ts`

**步骤**:
1. 实现 `StdioMcpClient implements McpClient`（JSON-RPC 消息格式）
2. 在 REPL 启动时连接 MCP server
3. 通过 `mcpToolToHarnessTool()` 将 MCP tools 注册到 ToolRegistry
4. 测试：Agent 自动发现并使用 MCP server 提供的工具

**学习要点**: MCP 协议、JSON-RPC、subprocess 通信、tool 动态注册

### 选题 5: 实现 Agentic RL 训练数据导出管道（高级，约 16 小时）

**目标**: 用 harness 收集轨迹，清洗，导出为 RL 训练格式

**涉及模块**: `src/trajectories/` `src/eval/`

**步骤**:
1. 设计一个任务集（20+ 个有明确成功标准的任务）
2. 用 harness 批量执行（需要批量 API 调用脚本）
3. 收集 trajectory JSON 文件
4. 实现清洗脚本：去重、去除失败轨迹、格式转换
5. 导出为 RLHF/DPO 训练格式（JSONL）

**学习要点**: trajectory 数据结构、训练数据工程、批量 agent eval

## 操作指南

### 选择一个选题并开始

```bash
# 1. 确认 harness 环境正常
npm run build && npm run typecheck && npm run eval

# 2. 阅读对应的源代码
# 选题 1: src/tools/core/file.ts（参考）
# 选题 2: src/agents/coding-agent.ts（参考）
# 选题 3: src/context/budget.ts + src/context/builder.ts
# 选题 4: src/mcp/adapter.ts + src/mcp/stdio.ts
# 选题 5: src/trajectories/exporter.ts + src/eval/runner.ts

# 3. 编写代码

# 4. 验证
npm run build && npm run typecheck && npm run eval
```

### 毕业设计项目的质量标准

一个好的毕业设计项目应该满足：

1. **`npm run build` 通过** — 无编译错误
2. **`npm run typecheck` 通过** — 无类型错误
3. **`npm run eval` 通过** — 现有 6 个 case 不被破坏
4. **新增 eval case** — 至少 1 个 case 覆盖新功能
5. **文档更新** — 更新相关 docs/*.md 和 README.md
6. **诚实标注** — 如果是部分实现，明确标注限制
