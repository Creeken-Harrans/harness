# 第五章 基于低代码平台的智能体搭建

## 原教程讲了什么

hello-agents 第五章以 Dify、Coze 等低代码平台为切入点，系统讲解了：

- **平台操作**：如何在可视化界面中配置 Agent——编写 System Prompt、选择 LLM 模型、添加知识库、勾选工具、发布为 API 或聊天机器人
- **工作流编排**：通过拖拽式节点编排多步骤 Agent 流程（条件分支、循环、工具调用）
- **知识库管理**：上传文档 → 向量化 → RAG 检索的完整配置流程
- **调试与发布**：平台内置的对话测试面板、日志查看、一键发布

**不足**：第一，低代码平台本质是**黑盒 Runtime**——Dify 内部的 Agent loop 如何构造 messages、如何处理 tool call、如何管理 context window，对用户完全不可见。出了 bug 只能靠平台日志，无法追踪到具体的 tool call delta 累积逻辑或 context 注入过程。第二，平台配置不可版本化——Prompt 调整、工具选择、知识库变更没有 git history，难以回滚和审计。第三，安全控制是平台级而非工具级——无法对单个工具设置不同的审批策略，也无法定义 workspace path policy 防止路径逃逸。

**本 harness 的改进**：将低代码平台的每个配置项映射为显式的 TypeScript 代码——System Prompt 对应 `SOUL.md` + `ContextBuilder.build()`，知识库对应 `MemoryStore` + `memory_search` tool，工具选择对应 `ToolRegistry`，上下文编排对应完整的 gather→select→structure→compress→budget 管道。每个环节都是可读、可改、可 git diff 的代码，而非黑盒配置。同时，安全控制下沉到工具级（risk 分级 + approval gate + path policy），trace jsonl 提供逐事件的完整可观测性。

## 本 Harness 如何映射

本 harness 不是低代码平台，而是 **code-first** 的 Agent Runtime——Dify/Coze 中每个可视化配置项，在 harness 中都有对应的显式 TypeScript 模块：

| Dify 概念 | Harness 对应模块 | 差异 |
|---|---|---|
| System Prompt 编辑器 | `SOUL.md` + `AGENTS.md` + `ContextBuilder.build()` | 文本文件，可 git diff、可版本回滚 |
| 知识库 / RAG | `MemoryStore` (`src/memory.ts`) + `memory_search` tool | 显式 JSON 存储 + 中文 bigram 搜索，而非黑盒向量库 |
| 工具选择 | `ToolRegistry` (`src/tools/registry.ts`) | 18 个 core tools，每个有 risk 分级和 inputSchema |
| 对话历史 | `SessionStore` (`src/session.ts`) | JSON 文件持久化，`data/sessions/*.json` |
| 上下文编排 | `src/context/` — gather → select → structure → compress → budget 五阶段管道 | 完全的可见性和控制力 |
| 调试 / 日志 | `TraceWriter` (jsonl 逐事件) + `TrajectoryRecorder` (JSON 聚合) | 结构化事件，而非平台内置日志面板 |
| 发布 API | `npm run dev` + REPL `/agent` 命令 | 本地运行，也可扩展为 HTTP server |

关键差异：低代码平台的 Agent loop 是固定的黑盒——你无法修改 tool call 的 delta 累积逻辑、无法插入自定义 approval gate、无法看到 context budget 的分配细节。而 harness 的每个环节都是可读、可改、可测试的 TypeScript 代码。这种 code-first 方式的价值不在于"比低代码更技术"，而在于**你可以精确控制 Agent 的每一个行为**。

## 原理解析：低代码平台的本质

Dify/Coze 等平台本质上是一个 **配置层 + 固定 Runtime**：

```
[Dify UI]
  ├─ Prompt 编辑 → 写入 system message
  ├─ 知识库配置 → 写入 RAG context
  ├─ 工具选择   → 写入 tool definitions
  └─ 发布/调试   → 调用固定 Agent loop
```

本 harness 的每一行代码都是对这套机制的"拆解版"：

| Dify 概念 | Harness 对应 |
|---|---|
| System Prompt | `ContextBuilder.build()` → `gatherContextSources()` → system source |
| 知识库 | `memory.search()` + SOUL.md + AGENTS.md + workspace index |
| 工具 | `ToolRegistry` — 注册/列表/执行/权限 |
| 对话历史 | `SessionStore` — data/sessions/*.json |
| 上下文窗口 | `ContextBudget` — maxTokens / usedTokens / dropped |
| 调试/日志 | `TraceWriter` — data/traces/*.jsonl |

## 操作指南

### 在 harness 中实现"Dify 风格"的配置

Dify 让你选择一个模型 + 写一段 system prompt + 选几个工具。在 harness 中，这等效于：

```bash
# 1. 选模型
DEEPSEEK_MODEL=deepseek-v4-pro npm run dev

# 2. 写 system prompt — 编辑 SOUL.md
cat > SOUL.md << 'EOF'
# SOUL.md
你是一个 Python 代码审查助手。审查代码时遵循 PEP 8 规范。
优先使用 read_file 和 grep 工具检查代码，不要直接猜测。
给出意见时附带具体行号和改进建议。
EOF

# 3. 选工具 — 所有 core tools 默认已注册，查看列表
/tools

# 4. 开始使用
you> 帮我审查 src/runtime/loop.ts
```

### 对比：Dify vs Harness

**Dify 的优势**（本 harness 没有的）：
- 可视化工作流编排
- 一键发布 API / Chatbot
- 内置 RAG 知识库管理
- 用户/权限管理

**Harness 的优势**（Dify 给不了的）：
- 全链路 streaming trace（jsonl 逐事件记录）
- 结构化 trajectory 导出
- 精确的 context budget 控制（gather → select → structure）
- 完整的安全边界控制（path policy、hard deny、approval gate）
- 可编程的 eval 回归测试
- Agent 范式可任意扩展（写新的 Agent 实现即可）

## 超越原教程

低代码平台的价值在于降低门槛。本 harness 的价值在于 **提高上限**。建议学习路径：

1. 先在 Dify 上理解 Agent 的概念（本章教程）
2. 再在 harness 上理解 Agent 的工程本质（本文档）

当你需要在 harness 上实现"Dify 知识库"时，你需要知道：
- 知识库 = `memory_add` tool（写入持久记忆）+ `memory_search` tool（语义搜索）
- Dify 的向量检索 = `src/memory/sqlite-store.ts` skeleton（TODO，需要集成 embedding）
- Dify 的多轮对话 = `SessionStore`（JSON 文件持久化）
- Dify 的上下文编排 = `ContextBuilder`（gather → select → structure → compress）

这些机制在 harness 中都是**显式的、可读的、可修改的 TypeScript 代码**，而非黑盒平台配置。

## 关键文件

| 文件 | 作用 |
|---|---|
| `src/context/builder.ts` | ContextBuilder — 相当于 Dify 的上下文编排 |
| `src/context/gather.ts` | gatherContextSources — 相当于 Dify 的知识/变量注入 |
| `src/tools/registry.ts` | ToolRegistry — 相当于 Dify 的工具管理 |
| `SOUL.md` | 项目级 system prompt — 相当于 Dify 的 Prompt 编辑器 |
| `src/memory.ts` | MemoryStore — 相当于 Dify 的知识库（简化版） |
