# 第十二章 智能体性能评估

## 原教程讲了什么

hello-agents 第十二章讲解 Agent 性能评估的方法论和工具链，覆盖：

- **评估维度**：任务成功率（task success rate）、工具调用效率（tool call efficiency——是否调用了不必要的工具）、回答质量（answer quality——是否正确、是否完整）、鲁棒性（对异常输入的容错）
- **评估指标**：Pass@k、F1、BLEU/ROUGE（文本质量）、tool selection accuracy（是否选了正确的工具）
- **Benchmark 生态**：BFCL（Berkeley Function Calling Leaderboard）评测 function calling 能力，GAIA 评测多步骤推理，SWE-bench 评测代码修复能力，WebArena 评测网页交互能力
- **自动化评估框架**：LLM-as-judge 的概念——用更强的模型评估 Agent 输出的质量

**不足**：第一，原教程停留在 **benchmark 概念介绍**——罗列了 BFCL、GAIA、SWE-bench 等 benchmark，但没有一个可以在本地运行的评估系统。读者学完后知道"有这些评估方法"，但无法对自己写的 Agent 做回归测试。第二，没有工具级回归测试——在对接真实 API 之前，无法验证 ToolRunner 的路径安全策略、工具调用的正确性、denied tool 的拒绝逻辑。第三，评估依赖外部 benchmark 和 API，无法在 CI 中零成本运行——每次改一行 tool 代码就得手动启动 Agent 测试。

**本 harness 的改进**：实现了一个最小但完整的 **eval harness**——`npm run eval` 直接运行，不消耗 API key。`runEvalSuite()` 从 `evals/cases/basic-tools.jsonl`（6 个基础用例）读取 case 定义，在独立的临时目录（`mkdtempSync`，用后清理）中通过 `ToolRunner` 直接执行（不经过 DeepSeek API），`approvalMode="never"` 自动批准所有非 dangerous 工具。提供 6 种 judge 规则：`final_contains`（输出包含指定文本）、`tool_called`（指定工具被调用）、`tool_not_called`（指定工具未被调用）、`permission_denied`（路径逃逸被拒绝）、`exit_ok`（所有工具调用成功）、`memory_hit`（记忆检索验证）。其中 `path-escape-denied` case 专门验证 workspace 安全策略。评估输出包含成功率、工具调用数、拒绝数、耗时、错误数——可直接在 CI 中运行。

## 本 Harness 如何映射

本 harness 实现了三层评估体系中的**第一层**——工具级回归测试，不消耗 API key，可直接在 CI 中运行：

| 层次 | 状态 | 说明 |
|---|---|---|
| Layer 1: Tool-level regression | **已实现** | 不调用 API，`ToolRunner` 直接执行预定义 toolCalls |
| Layer 2: Agent-level eval | TODO | 真实 DeepSeek API 调用，测试完整 Agent loop |
| Layer 3: LLM-as-judge | TODO | 用 DeepSeek 评估 Agent 输出质量 |

**当前 Eval 工作流**：
```
evals/cases/basic-tools.jsonl (6 cases)
  → runEvalSuite()
    → 每个 case: mkdtempSync 创建隔离数据目录
      → ToolRunner 直接执行 toolCalls (绕过 DeepSeek API, approvalMode="never")
        → judgeEvalCase() 规则判定
          → finally: fs.rmSync 清理临时目录
            → computeMetrics() 汇总统计
```

核心文件：
- `src/eval/runner.ts` — `runEvalSuite()`：读取 cases 文件 → 逐 case 执行 → 独立 tmp 环境 → 用后清理
- `src/eval/cases.ts` — `EvalCase`（`toolCalls` + `judge` 规则 + `allowedTools`/`deniedTools`）类型定义
- `src/eval/judge.ts` — 6 种 judge 规则：`final_contains` / `tool_called` / `tool_not_called` / `permission_denied` / `exit_ok` / `memory_hit`
- `src/eval/metrics.ts` — `computeMetrics()`：成功率、工具调用数、拒绝数、耗时、错误数
- `evals/cases/basic-tools.jsonl` — 6 个基础用例：memory 读写、shell echo、file 读写、path-escape 拒绝、git 状态、notes/todo

## 原理解析：分层评估设计

hello-agents 教程介绍了多个 benchmark（BFCL、GAIA、SWE-bench 等）。本 harness 当前实现的评估是**最小层**：工具级回归测试。

评估层次规划：

```
Layer 1: Tool-level regression (当前已实现)
  └─ 不调用 API，直接测 ToolRunner
  └─ 6 cases: memory, shell, file, path-escape, git, notes/todo

Layer 2: Agent-level eval (TODO，需要 API key)
  └─ 真实 DeepSeek API 调用
  └─ 测试完整 Agent loop (思考 → 工具调用 → 回答)

Layer 3: LLM-as-judge (TODO)
  └─ 用 DeepSeek 评估 Agent 输出质量
  └─ 替代规则判定
```

### Eval Runner 的工作流程

```typescript
async function runCase(evalCase: EvalCase): Promise<EvalCaseResult> {
  // 1. 为每个 case 创建独立的临时环境（隔离）
  const { runner, dataDir } = makeRunner();  // approvalMode="never"，tmp dataDir

  // 2. 按 case 定义的工具调用顺序执行
  for (const call of evalCase.toolCalls) {
    // 3. 跳过 denied tools
    if (evalCase.deniedTools?.includes(call.name)) { deniedToolCount++; continue; }
    // 4. 通过 ToolRunner 直接执行（不经过 DeepSeek API）
    const result = await runner.run(call);
    // 5. 判断工具是否成功 + 是否被拒绝
    if (!ok && /denied|refusing|escapes/.test(result)) deniedToolCount++;
  }

  // 6. 规则判定
  return judgeEvalCase(evalCase, partial);
}
```

关键设计：
- **不调用 API**：toolCalls 在 case 定义中显式给出，直接传给 ToolRunner
- **独立环境**：每个 case 使用 `mkdtempSync` 创建的临时目录（用后清理）
- **approvalMode="never"**：eval 自动批准所有非 dangerous 工具

### 6 种 Judge 规则

| Judge | 判定逻辑 |
|---|---|
| `final_contains` | 最终输出中包含指定文本 |
| `tool_called` | 指定的工具被调用了 |
| `tool_not_called` | 指定的工具没有被调用 |
| `permission_denied` | 有工具被拒绝（路径逃逸或权限不足） |
| `exit_ok` | 所有工具调用都成功 (`ok: true`) |
| `memory_hit` | 最终输出中包含指定文本（用于验证记忆检索） |

## 操作指南

### 运行 Eval

```bash
npm run eval
```

输出：
```json
{
  "total": 6,
  "passed": 6,
  "failed": 0,
  "successRate": 1,
  "toolCallCount": 8,
  "deniedToolCount": 1,
  "durationMs": 40,
  "errors": 0

```

### 查看具体 Case 结果

```bash
# 查看最新报告
cat evals/reports/report-*.json | python3 -m json.tool | head -100
```

### 添加新的 Eval Case

在 `evals/cases/basic-tools.jsonl` 中添加一行：

```jsonl
{"id":"my-test","name":"my new test","input":"test something","allowedTools":["read_file","grep"],"judge":[{"type":"tool_called","name":"read_file"},{"type":"exit_ok"}],"tags":["custom"],"toolCalls":[{"name":"read_file","arguments":{"path":"package.json"}},{"name":"grep","arguments":{"query":"deepseek"}}]}
```

每个字段说明：
- `id`: 唯一标识
- `name`: 可读名称
- `allowedTools`: 允许执行的工具白名单
- `deniedTools`: 预期被拒绝的工具
- `judge`: 判定规则（单个或数组）
- `toolCalls`: 依次执行哪些工具、传什么参数
- `tags`: 标签（用于分类统计）

### 运行单个 Case

修改 `runner.ts` 中的 `runEvalSuite` 调用，或在 REPL 中手动测试工具：

```bash
npm run dev
# 测试 path escape
you> read_file /etc/passwd
# 应该看到 "Path escapes HARNESS_WORKSPACE." 拒绝信息
```
