# 第十五章 构建赛博小镇

## 原教程讲了什么

hello-agents 第十五章是全书最宏大的综合案例——构建一个"赛博小镇"（模拟小镇），系统展示了多 Agent 协作的前沿概念，覆盖：

- **多 Agent 角色定义**：小镇中的每个居民是一个 Agent，拥有不同的 system prompt（面包师、图书管理员、镇长、医生等）和不同的能力（工具集）
- **Agent 间通信**：Agent 之间可以发送消息、请求任务、共享信息——例如镇长向面包师下发"明天需要 100 个面包"的任务
- **共享世界状态**：所有 Agent 运行在同一个"小镇"环境中，共享物品库存、天气状态、公共事件
- **调度机制**：时间推进系统——早上 8 点面包师开始工作，晚上 10 点所有店铺关门，事件按时间线触发
- **社交网络**：Agent 之间的朋友关系、信任度、信息传播

**不足**：第一，赛博小镇是一个**领域特定的多 Agent 框架**——Agent 角色定义、世界状态管理、调度逻辑都紧密耦合在小镇场景中。如果要构建一个"模拟公司"而非"模拟小镇"，需要大量重写。第二，多 Agent 通信与 Agent 运行时耦合——Agent 的"大脑"（推理循环）和"社交能力"（通信协议）混在一起，无法将通信层独立出来复用到其他多 Agent 场景。第三，缺少通用的 Agent 间通信接口——A2A 通信是隐式的，没有显式的 `AgentCard`（能力描述）、`AgentBus`（消息总线）、task request/response 契约。

**本 harness 的改进**：虽然"赛博小镇"级别（数十个 Agent、持续运行、社交网络）的多 Agent 系统超出了当前 4400 行 harness 的范围，但 harness 提供了三个关键的多 Agent 基础设施。第一，**Agent 角色定义通过 prompt 合约**——不同角色就是不同的 system instruction，不需要写新的 Agent 类（6 种 agent mode 已经是这个模式的证明）。第二，**`LocalAgentBus`** 提供了进程内 Agent 通信的干净接口——`registerAgent(card: AgentCard, handler)` 注册 Agent 能力描述，`requestTask(name, input)` 发起任务请求，通信层与 Agent runtime 解耦。第三，**共享状态机制**——`Workspace`（文件系统）+ `MemoryStore`（持久记忆）+ `NotesStore`（任务笔记）天然是多 Agent 的共享世界，Agent 间可以通过文件进行"异步通信"（一个 Agent 写 research_notes.md，另一个 Agent 读取）。所有 A2A 模块明确标注 "Current support is local in-process bus, not remote protocol"——诚实标注实现状态。

## 本 Harness 如何映射

本 harness 的 A2A 模块提供了多 Agent 通信的基础骨架。但"赛博小镇"级别（数十个 Agent、持续运行、社交网络）的多 Agent 系统超出了当前 harness 的范围。

核心文件：
- `src/a2a/local-bus.ts` — `LocalAgentBus`，进程内 Agent 注册和调用
- `src/a2a/agent-card.ts` — `AgentCard`，Agent 能力描述

## 原理解析：从单 Agent 到多 Agent 的关键跨越

hello-agents 的赛博小镇案例展示了多 Agent 系统的核心概念：

1. **Agent 角色定义** — 每个 Agent 有不同的 system prompt 和能力
2. **Agent 间通信** — Agent 之间可以发送消息、请求任务
3. **环境共享** — 所有 Agent 在同一个"世界"中运行
4. **调度机制** — 决定哪个 Agent 何时执行

本 harness 目前具备的能力：

### Agent 角色定义 ✓

通过 `createAgent(name)` + 不同的 system prompt / SOUL.md 即可定义不同角色：

```
Agent A: "你是小镇的图书管理员，职责是管理图书借阅..."
Agent B: "你是小镇的面包师，职责是烘焙面包和接待顾客..."
Agent C: "你是小镇的镇长，职责是协调公共事务..."
```

### Agent 间通信 △ (skeleton)

`LocalAgentBus` 提供了进程内通信骨架：

```typescript
const bus = new LocalAgentBus();

// 注册 Agent
bus.registerAgent(
  { name: "librarian", description: "图书管理员", capabilities: ["search_books", "lend_book"] },
  async (input) => { /* 调用 librarian agent */ }
);

// Agent 间通信
const result = await bus.requestTask("librarian", { task: "find_book", title: "..." });
```

### 环境共享 ✓

通过共享 `Workspace`、`MemoryStore`、`NotesStore`，多个 Agent 可以操作同一套文件、记忆、笔记。这为多 Agent 提供了"共享世界"。

### 调度机制 △ (TODO)

当前没有实现自动调度。在完整的"赛博小镇"中，需要一个调度器决定"现在是早上 8 点，面包师应该开始烤面包了"。

## 操作指南

### 体验最小多 Agent：两个 Agent 协作

虽然本 harness 是单 Agent CLI，但你可以通过 **切换 agent mode + 共享 session** 体验基本的多 Agent 协作：

```bash
# Terminal 1: 启动 harness（假设有共享 session 支持）
npm run dev -- --session=town

# 当前是 simple agent，作为"规划师"角色
you> 小镇需要一个新公园，你来规划设计

# 手动切换角色：编辑 SOUL.md 改变 agent 行为
# 或者直接在新的对话轮次中以不同角色提问
```

### 模拟 Agent 间通信

更实际的做法：将 A2A LocalAgentBus 概念应用于实际工作流。

例如，CodingAgent + ResearchAgent 协作完成一个任务：

```bash
# Step 1: ResearchAgent 收集信息
/agent research
you> 研究 TypeScript 中 AsyncGenerator 的最佳实践，记录到 research_notes.md

# Step 2: CodingAgent 基于研究结果写代码
/agent coding
you> 根据 research_notes.md 中的最佳实践，重构 src/runtime/loop.ts
```

两个 Agent 共享同一个 workspace、session 和 notes，实现了"基于文件的 Agent 间通信"。

### 真正的多 Agent（未来扩展方向）

`src/a2a/local-bus.ts` 的 `LocalAgentBus` 已经定义好了接口。未来实现真正的多 Agent 协作需要：

1. 一个 `TownScheduler` 类：管理 Agent 的生命周期和调度
2. 多个 `AgentRuntime` 实例：每个 Agent 独立运行
3. 共享 `LocalAgentBus`：Agent 间通信
4. 共享 `Workspace` + `MemoryStore`：共享世界状态

## 超越原教程

对于"赛博小镇"级别的多 Agent 系统，本 harness 的价值不在于"已经实现"，而在于：

1. **清晰的单 Agent 基础**：先理解一个 Agent 如何工作（第七章），再扩展到多 Agent
2. **解耦的通信层**：A2A bus 独立于 Agent runtime，不耦合
3. **共享状态机制**：workspace + memory + notes 是天然的多 Agent 共享状态
4. **诚实标注**：A2A 模块明确标注 "Current support is local in-process bus, not remote protocol"

| hello-agents 第十五章 | 本 harness |
|---|---|
| 完整赛博小镇实现 | A2A skeleton + 单 Agent 基础 |
| 特定领域的多 Agent 框架 | 通用的 AgentBus 接口 + 解耦设计 |
| Python 实现 | TypeScript 骨架，接口先行 |
