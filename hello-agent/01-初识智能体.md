# 第一章 初识智能体

## 原教程讲了什么

介绍智能体的基本概念：感知环境、推理决策、执行动作、观察反馈。以简单的 LLM 调用为例展示"模型 + 工具"的最小智能体形态。

## 本 Harness 如何映射

本 harness 的最小智能体体验就藏在 `npm run dev` 之后的一次对话中。核心文件：

- `src/main.ts` — 薄入口，仅 8 行
- `src/cli/repl.ts` — REPL 组装线，把所有模块连线
- `src/runtime/runtime.ts` — `AgentRuntime`，智能体的"大脑"
- `src/runtime/loop.ts` — `runAgentLoop`，感知→推理→执行→观察的主循环
- `src/agents/simple-agent.ts` — 默认的 `SimpleAgent`，直接委托给 runLoop

## 原理解析：Agent 主循环的本质

hello-agents 教程中的"智能体"可以简化为：

```
用户输入 → LLM 推理 → (如果需要工具) → 执行工具 → 观察结果 → LLM 再推理 → ... → 最终回答
```

本 harness 把这个循环实现在 `src/runtime/loop.ts` 的 `runAgentLoop` 函数中。它的核心是一个 **AsyncGenerator**：

```typescript
export async function* runAgentLoop(deps, input): AsyncGenerator<AgentEvent, AgentResult> {
  // 1. 初始化 trace / trajectory
  // 2. 构造 messages (system + history + user input)
  // 3. for (steps < maxSteps) {
  //      a. DeepSeekClient.chatStream() — 流式推理
  //      b. 累积 content / reasoning_content / tool_call delta
  //      c. 如果没有 tool_calls → 返回 final answer
  //      d. 遍历 tool_calls → ToolRunner.runWithEvents() — 执行并观察
  //      e. 将 tool result 序列化为 tool message 追加到 messages
  //    }
  // 4. 达到 maxSteps → 返回截断提示
}
```

**关键设计决策**：为什么用 AsyncGenerator 而不是普通 async/await？

- **逐事件产出**：CLI 可以实时打印 `llm_delta`、`tool_stdout` 等，TraceWriter 同步写 jsonl，TrajectoryRecorder 同步记录
- **可中断**：调用方 (`AgentRuntime.run()`) 可以在任何时候停止迭代（未来用于 cancellation）
- **单一出口**：所有行为最终收敛为 `AgentResult`，包含 `runId`、`finalText`、`steps`、`stoppedReason`

这就是"hello-agents 第一章"在本 harness 中的工程化实现：不是 `while True: response = llm.chat()` 的同步循环，而是一个完整的 streaming event loop。

## 操作指南

### 体验最小智能体

```bash
npm run dev
```

启动后，你会看到：

```
DeepSeek Mini Harness
session=default model=deepseek-v4-flash workspace=/home/...
Type /help for commands. Type /exit to quit.
```

输入一句话就能看到完整的 Agent 工作流：

```
you> 列出当前目录的文件
```

你会实时看到：
1. `reasoning> ...` (如果开启了 thinking)
2. `assistant> ...` — 模型逐字输出
3. `[tool] list_dir start` — 工具被调用
4. 工具输出
5. `[tool] list_dir ok`
6. 最终回答

### 查看内部发生了什么

```bash
# 查看 trace（每次交互的完整事件记录）
cat data/traces/<runId>.jsonl | head -20

# 查看 trajectory（结构化轨迹）
cat data/trajectories/<runId>.json | python3 -m json.tool | head -40
```

### 理解 AgentEvent 流

在 `src/runtime/events.ts` 中，`AgentEvent` 是一个 discriminated union，涵盖所有运行时事件：

| 事件 | 含义 |
|---|---|
| `user_message` | 用户输入 |
| `llm_delta` | 模型逐字输出 |
| `llm_reasoning_delta` | 模型思考过程（DeepSeek reasoning_content） |
| `assistant_message` | 模型完成一次输出（含 tool_calls） |
| `tool_call_start` | 工具开始执行 |
| `tool_stdout` / `tool_stderr` | 工具实时输出 |
| `tool_call_end` | 工具执行完成 |
| `trace` | 元信息（trace 文件路径等） |
| `error` | 错误 |
| `done` | 一次 run 结束，带有 AgentResult |

## 超越原教程

| hello-agents 第一章 | 本 harness |
|---|---|
| 同步 `llm.chat()` 调用 | 全链路 AsyncGenerator streaming |
| print 调试 | 结构化 `AgentEvent` + jsonl trace |
| 无状态追踪 | `runId` 贯穿整个生命周期 |
| 无工具调度框架 | `ToolRegistry` + `ToolRunner` 解耦 |
| 仅概念演示 | 可直接 `npm run dev` 交互 |
