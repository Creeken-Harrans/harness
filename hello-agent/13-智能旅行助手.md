# 第十三章 智能旅行助手

## 原教程讲了什么

hello-agents 第十三章是一个综合实践案例，以"智能旅行助手"为目标，系统展示了如何将前面的知识组合成一个完整的 Agent 应用，覆盖：

- **需求分析**：旅行助手需要什么能力——搜索景点信息、查询天气/交通、推荐美食、制定多日行程、生成旅行报告
- **工具集成**：将多个 API（搜索 API、天气 API、地图 API）封装为 Agent 可调用的工具，在 Agent 内部调度
- **多步骤规划**：Agent 按"收集信息 → 分析偏好 → 制定行程 → 保存结果"的多阶段流程执行
- **最终输出**：将旅行计划保存为结构化文件

**不足**：第一，旅行助手被实现为一个**专用 Python 脚本**——搜索逻辑、规划逻辑、输出格式都硬编码在 Agent 代码中。如果你需要一个新的"料理推荐助手"，需要重写大部分代码，而非复用现有框架。第二，工具和 Agent 代码耦合——搜索工具直接写在 Agent 的 run 方法中，无法被其他 Agent 复用。第三，没有规划过程记录——Agent 执行完后，无法回溯它做了哪些步骤、每一步的结果是什么。第四，没有持久化输出机制——最终行程只是 print 到终端，没有自动写文件。

**本 harness 的改进**：本 harness **不提供"旅行助手代码"，而是提供构建旅行助手所需的全部通用组件和组合方法**。相当于 hello-agents 给你一个做好的蛋糕，harness 给你面粉、鸡蛋、烤箱和烘焙原理。具体地：搜索靠 `grep` / `glob` / `read_file` 等文件工具（如果资料在 workspace 中），规划靠 `PlanExecuteAgent`（先列计划、逐步执行、自动标记完成），过程记录靠 `todo_add` / `note_append`（每一步可回溯），结果输出靠 `write_file`（保存为 Markdown 文件）。行为定制通过 `AGENTS.md` 而非代码修改——写一段旅行助手的规则文本即可切换身份。换一个领域（如料理推荐），只需要换 AGENTS.md 内容，零行代码改动。全部 ToolRegistry 中的工具（file、grep、notes、todo）跨 Agent 复用。

## 本 Harness 如何映射

本章不再引入新的模块，而是展示如何**组合已有模块**完成一个综合任务。旅行助手本质上是一个多步骤 Agent 任务，可以用 harness 的 `plan` mode + 已有工具完成。

核心能力组合：

- **搜索信息** → `grep` / `glob` / `read_file` (从本地文档获取信息)
- **记录计划** → `todo_add` / `note_append` (记录旅行计划)
- **保存结果** → `write_file` (生成行程文件)
- **多步骤执行** → `PlanExecuteAgent` (先规划，再逐步执行)

## 原理解析：复杂任务 = 工具组合 + Agent Mode

hello-agents 的旅行助手案例需要多个工具（搜索、天气、地图等）和一个规划循环。本 harness 的方法：

1. **不需要专门写"旅行 Agent"** — `PlanExecuteAgent` + system prompt 即可
2. **搜索靠文件工具** — 如果 wiki/travel 资料在 workspace 中，grep/glob 可以作为"本地搜索"
3. **记录靠 notes** — todo 跟踪任务步骤，NOTES.md 保存规划细节
4. **输出靠 write_file** — 最终行程保存为 Markdown 文件

### "超越"原教程的含义

hello-agents 教程给你一个旅行助手的示例代码。本 harness 给你的不是"旅行助手代码"，而是**构建旅行助手需要的所有通用组件**，以及**组合它们的方法**。

这类似于：
- hello-agents: 给你一个做好的蛋糕
- 本 harness: 给你面粉、鸡蛋、烤箱，以及烘焙原理

## 操作指南

### 构建旅行助手

```bash
npm run dev

# 1. 切换到 plan mode
/agent plan

# 2. 如果有旅行资料（可选）
# 把旅行资料放到 workspace 中，Agent 可以通过 grep/read_file 搜索

# 3. 提出任务
you> 帮我规划一个 3 天的东京旅行计划。包括景点、交通、美食推荐。
     先做 research（搜索 workspace 中的资料），
     然后制定详细行程，
     最后保存为 tokyo_trip.md。
```

Agent 会：
1. 调用 `grep` 搜索资料中的 "Tokyo"、"东京"、"景点"
2. 调用 `read_file` 读取相关文档
3. 调用 `todo_add` 添加 "规划第1天行程"、"规划第2天行程"、"规划第3天行程"、"保存最终文件"
4. 逐步完成每一天的规划
5. 调用 `write_file` 保存 `tokyo_trip.md`

### 定制旅行助手的 System Prompt

编辑 `SOUL.md` 或创建 AGENTS.md：

```markdown
# AGENTS.md — 旅行助手规则

你是专业旅行规划助手。

规划原则：
1. 每天不超过 3 个主要景点，留出休息时间
2. 交通方式优先地铁，给出具体线路
3. 美食推荐给出具体店名和人均价格
4. 行程保存为 Markdown 格式，包含时间线

输出格式：
- 先做 overview（3-5 句话）
- 再输出每日详细行程
- 最后保存文件并报告路径
```

### 对比：专用 Agent vs 通用 Harness

hello-agents 的旅行助手是一个专用 Python 脚本。本 harness 的方法是：

1. 通用 `PlanExecuteAgent`（不写一行新代码）
2. 通过 AGENTS.md 定制行为（markdown 配置）
3. 所有工具（file, todo, notes）复用已有 ToolRegistry
4. trace/trajectory 自动记录每次规划过程

如果你需要一个新的"料理推荐助手"，不需要写新 Agent——只需要换个 AGENTS.md 内容。

## 超越原教程

| hello-agents 第十三章 | 本 harness |
|---|---|
| 专用旅行助手脚本 | 通用 harness + PlanExecuteAgent + AGENTS.md 定制 |
| 硬编码工具 | 复用 ToolRegistry 中的 file/grep/notes/todo 工具 |
| 无规划记录 | todo_add 跟踪任务进度 + NOTES.md 记录过程 |
| 无持久输出 | write_file 保存最终行程为 Markdown |
| 无轨迹 | 每次规划的 trace 和 trajectory 自动保存 |
| 换领域需重写 | 换 AGENTS.md 即可切换助手身份 |
