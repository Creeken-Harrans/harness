# 第十二章 智能体性能评估

## 原教程讲了什么

Agent 评估方法论：评估维度、评估指标、benchmark 介绍、自动化评估框架。

## 本 Harness 如何映射

本 harness 实现了一个最小但完整的 **eval harness**，不依赖真实 API 调用即可进行工具级回归测试。

核心文件：

- `src/eval/runner.ts` — `runEvalSuite()`，从 cases 文件读取并执行
- `src/eval/cases.ts` — `EvalCase` / `EvalCaseResult` / `EvalJudge` 类型
- `src/eval/judge.ts` — `judgeEvalCase()`，规则判定
- `src/eval/metrics.ts` — `computeMetrics()`，统计成功率/工具调用数/耗时
- `evals/cases/basic-tools.jsonl` — 6 个基础用例

## 原理解析：分层评估设计

hello-agents 教程介绍了多个 benchmark（BFCL、GAIA、SWE-bench 等）。本 harness 当前实现的评估是**最小层**：工具级回归测试。

评估层次规划：

```
Layer 1: Tool-level regression (当前已实现)
  └─ 不调用 API，直接测 ToolRunner
  └─ 6 cases: memory, shell, file, path-escape, git, notes/todo

Layer 2: Agent-level eval (TODO，需要 API key)
  └─ 真实 DeepSeek API 调用
  └─ 测试完整 Agent loop (思考 → 工具调用 → 回答)

Layer 3: LLM-as-judge (TODO)
  └─ 用 DeepSeek 评估 Agent 输出质量
  └─ 替代规则判定
```

### Eval Runner 的工作流程

```typescript
async function runCase(evalCase: EvalCase): Promise<EvalCaseResult> {
  // 1. 为每个 case 创建独立的临时环境（隔离）
  const { runner, dataDir } = makeRunner();  // approvalMode="never"，tmp dataDir

  // 2. 按 case 定义的工具调用顺序执行
  for (const call of evalCase.toolCalls) {
    // 3. 跳过 denied tools
    if (evalCase.deniedTools?.includes(call.name)) { deniedToolCount++; continue; }
    // 4. 通过 ToolRunner 直接执行（不经过 DeepSeek API）
    const result = await runner.run(call);
    // 5. 判断工具是否成功 + 是否被拒绝
    if (!ok && /denied|refusing|escapes/.test(result)) deniedToolCount++;
  }

  // 6. 规则判定
  return judgeEvalCase(evalCase, partial);
}
```

关键设计：
- **不调用 API**：toolCalls 在 case 定义中显式给出，直接传给 ToolRunner
- **独立环境**：每个 case 使用 `mkdtempSync` 创建的临时目录（用后清理）
- **approvalMode="never"**：eval 自动批准所有非 dangerous 工具

### 6 种 Judge 规则

| Judge | 判定逻辑 |
|---|---|
| `final_contains` | 最终输出中包含指定文本 |
| `tool_called` | 指定的工具被调用了 |
| `tool_not_called` | 指定的工具没有被调用 |
| `permission_denied` | 有工具被拒绝（路径逃逸或权限不足） |
| `exit_ok` | 所有工具调用都成功 (`ok: true`) |
| `memory_hit` | 最终输出中包含指定文本（用于验证记忆检索） |

```bash

cat evals/reports/report-*.json | python3 -m json.tool | head -100
```

### 添加新的 Eval Case

在 `evals/cases/basic-tools.jsonl` 中添加一行：

```jsonl
{"id":"my-test","name":"my new test","input":"test something","allowedTools":["read_file","grep"],"judge":[{"type":"tool_called","name":"read_file"},{"type":"exit_ok"}],"tags":["custom"],"toolCalls":[{"name":"read_file","arguments":{"path":"package.json"}},{"name":"grep","arguments":{"query":"deepseek"}}]}
```

每个字段说明：
- `id`: 唯一标识
- `name`: 可读名称
- `allowedTools`: 允许执行的工具白名单
- `deniedTools`: 预期被拒绝的工具
- `judge`: 判定规则（单个或数组）
- `toolCalls`: 依次执行哪些工具、传什么参数
- `tags`: 标签（用于分类统计）

### 运行单个 Case

修改 `runner.ts` 中的 `runEvalSuite` 调用，或在 REPL 中手动测试工具：

```bash
npm run dev
# 测试 path escape
you> read_file /etc/passwd
# 应该看到 "Path escapes HARNESS_WORKSPACE." 拒绝信息
```
