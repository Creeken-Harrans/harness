# 第二章 智能体发展史

## 原教程讲了什么

从符号主义到反应式、从 BDIAgent 到 LLM Agent，梳理智能体范式的演进脉络。

## 本 Harness 如何映射

本 harness 不是历史博物馆，但它的架构天然支持多种范式：

- **反应式** → `SimpleAgent`：输入→推理→输出，无内部状态机
- **ReAct** → `ReactAgent`：Thought → Action → Observation 循环
- **Plan-Execute** → `PlanExecuteAgent`：先规划后执行，todo 跟踪
- **Reflection** → `ReflectionAgent`：执行后自检修正

核心在于 `src/agents/` 目录下的 agent family 设计。

## 原理解析：Agent 范式的本质差异

hello-agents 教程中，不同范式通常需要不同的代码框架。但本 harness 使用统一的 **prompt-contract agent mode** 设计：

```typescript
// src/agents/agent.ts
export interface Agent {
  name: string;
  description: string;
  run(input: string, ctx: AgentContext): AsyncGenerator<AgentEvent, AgentResult>;
}
```

所有 agent mode 都实现同一个接口，差异仅在于它们注入给 `runLoop()` 的 system instruction 不同。

以 `ReactAgent` 为例（`src/agents/react-agent.ts`）：

```typescript
run(input: string, ctx: AgentContext): AsyncGenerator<AgentEvent, AgentResult> {
  const instruction = [
    "Use a ReAct-style loop internally: decide the next action, " +
    "call a tool when useful, observe the result, and continue " +
    "until the task is answered.",
    "Do not reveal private chain-of-thought.",
    "Stop after the configured max steps and explain what remains.",
  ].join("\n");
  return ctx.runLoop(agentInput(instruction, input));
}
```

**关键洞察**：ReAct、Plan-Execute、Reflection 的本质区别不在于代码流程不同，而在于 **prompt 合约不同**。ReAct 要求模型在每个 action 前隐式思考，Plan 要求先输出 visible plan，Reflection 要求最后做一次自检。这三种行为都可以通过 system prompt 指令 + 同一个 DeepSeek tool-calling loop 实现。

## 操作指南

### 切换 Agent 范式

```bash
# 方式 1：环境变量
HARNESS_AGENT=react npm run dev

# 方式 2：REPL 内切换
/agent react
/agent plan
/agent reflection
/agent coding
/agent research
/agent simple
```

### 观察不同范式的行为差异

用同一个任务测试不同 agent：

```
you> 帮我检查这个项目有没有 CI 配置文件
```

- `simple`：直接调用 glob/grep 工具查找，报告结果
- `react`：先搜索，分析结果，可能需要额外步骤，但行为类似 core loop
- `plan`：先列出步骤（1.搜索 CI 配置 2.分析内容 3.报告），再逐步执行
- `coding`：先检查 README/package.json，再 glob 搜索，符合 inspect-first 风格

**注意**：当前所有 agent mode 都委托给同一个 `runLoop`，行为差异主要通过 system prompt 实现。这不是简化版——这恰恰是 LLM Agent 的核心设计哲学：**用自然语言指令而非代码分支来控制行为**。

## 超越原教程

| hello-agents 第二章 | 本 harness |
|---|---|
| 历史回顾为主 | 可实际运行、切换不同范式 |
| 范式间代码不统一 | 统一 Agent 接口 + prompt-contract |
| 无工具集成 | 每个 mode 都共享同一套 ToolRegistry |
| 概念性 ReAct | `ReactAgent` 在 tool-calling loop 上运行 |
| 无 Plan-Execute 实现 | `PlanExecuteAgent` 有可见 plan + todo 记录 |
