# 第八章 记忆与检索

## 原教程讲了什么

Agent 记忆系统的概念、短期记忆（对话历史）、长期记忆（持久存储）、RAG 检索增强生成。

## 本 Harness 如何映射

本 harness 区分并实现了多个层次的记忆，核心文件：

- `src/memory.ts` — **兼容层 MemoryStore**，基于 JSON 文件的持久记忆
- `src/memory/memory.ts` — **MemoryStoreInterface**，定义了 working/episodic/semantic/procedural 四种记忆类型
- `src/memory/json-store.ts` — **JsonMemoryStore**，包装兼容层，适配新接口
- `src/memory/search.ts` — 搜索工具函数（关键词 + 中文二字词）
- `src/memory/sqlite-store.ts` — **SqliteMemoryStore skeleton**（TODO）
- `src/session.ts` — **SessionStore**，会话历史（短期记忆）
- `src/notes/` — **Notes/Todo/Decisions/Errors/Progress**，任务级记忆
- `src/context/gather.ts` — 记忆注入 context 的入口

## 原理解析：记忆层次架构

hello-agents 教程将记忆分为短期（对话上下文）和长期（持久存储+RAG）。本 harness 进行了更细致的分层：

```
┌──────────────────────────────────────────────────┐
│ Context Builder (每次 LLM 调用前构建)              │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ Session   │ │ Memory   │ │ SOUL + AGENTS.md │  │
│  │ History   │ │ Search   │ │ (static rules)   │  │
│  │ (短期)    │ │ (长期)    │ │                  │  │
│  └──────────┘ └──────────┘ └──────────────────┘  │
├──────────────────────────────────────────────────┤
│ Notes/Todo (任务状态)                              │
│  NOTES.md / TODO.md / DECISIONS.md / ERRORS.md    │
│  (通过工具访问，不自动注入 context)                  │
├──────────────────────────────────────────────────┤
│ Memory Store (持久层)                              │
│  data/memory.json  ←── 当前实现                    │
│  [future] SQLite + vector ←── TODO                 │
└──────────────────────────────────────────────────┘
```

### 为什么 Notes 不自动注入 Context？

这是一个有意识的设计决策。Notes（NOTES.md, TODO.md, DECISIONS.md, ERRORS.md, PROGRESS.md）是**长程任务状态**，而非每次推理都需要的信息。如果每次 LLM 调用都注入全部 notes，会大量消耗 context budget。

替代方案：Agent 通过 `note_read`、`todo_list` 等工具**按需访问** notes。这更接近人类的工作方式——你不会每 5 分钟重读一遍所有笔记，而是需要时才查阅。

### 记忆搜索：中文友好设计

`src/memory.ts` 的 `search()` 方法同时处理英文关键词和中文二字词（bigram）：

```typescript
function terms(input: string): Set<string> {
  // 英文/数字 token: 匹配 \p{L}\p{N}_- 连续字符 (>=2)
  for (const m of s.matchAll(/[\p{L}\p{N}_-]+/gu)) {
    if (token.length >= 2) out.add(token);
  }
  // 中文: 单字 + 相邻二字词 (bigram)
  const han = [...s.matchAll(/[\p{Script=Han}]/gu)].map(m => m[0]);
  for (let i = 0; i < han.length; i++) {
    out.add(han[i]);
    if (i + 1 < han.length) out.add(han[i] + han[i + 1]);
  }
}
```

这使得"用户偏好"可以匹配到"用户"和"偏好"的二字组合，不需要 embedding 也能做基本的语义对齐。

### memory_add 工具的行为

当模型调用 `memory_add` 工具时（`src/tools/core/memory.ts`）：

```typescript
run(input, ctx) {
  const entry = ctx.memory.add(text, tags, "assistant");
  return { ok: true, content: `Saved memory ${entry.id}`, data: { saved: entry } };
}
```

注意 `source: "assistant"` — 这标记了这条记忆是由 Agent 主动保存的，与用户通过 `/remember` 命令手动保存的记忆（`source: "manual"`）区分开。

## 操作指南

### 手动管理记忆

```bash
npm run dev

# 手动保存记忆
/remember DeepSeek API 默认 base URL 是 https://api.deepseek.com

# 搜索记忆
/mem DeepSeek URL

# 列出所有记忆
/mem

# 查看记忆文件
cat data/memory.json | python3 -m json.tool
```

### 让 Agent 自动使用记忆

```
you> 记住：这个项目的代码风格是 2 空格缩进，不用 tab
```

模型收到这个指令后，应该调用 `memory_add` 工具保存这条偏好。下次对话时，`ContextBuilder` 会通过 `memory.search(latestUserInput, 8)` 检索相关记忆并注入 context。

验证：
```bash
# 查看本次 context build 中是否注入了记忆
/context
# 输出中的 "memoryHits" 字段表示本次命中的记忆数
```

### 查看 notes 系统

```bash
# 查看所有 notes 文件
ls data/notes/

# Plan agent 会自动写 todo
/agent plan
you> 帮我重构 src/runtime/loop.ts，拆成更小的函数

# 查看自动记录的 todo
/todo
```
